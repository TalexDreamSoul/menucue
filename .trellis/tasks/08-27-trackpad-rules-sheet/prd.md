# 触控板规则表格化与弹窗编辑器

## 背景

用户反馈（2026-08-28）：「触摸板规则改成 table 可以新增 + 弹窗那种，现在的怪怪的」。现状是规则行内联展开出 15–25 个字段的编辑器（TrackpadSettingsView 内），层级深、页面被撑爆。目标交互 = 设计稿画板 B（规则表格）+ 画板 C（三段式弹窗编辑器），该形态在 IA 重组任务中被有意留后，现在落地。

## Requirements

### R1. 规则表格（画板 B 形态）
- 每行：启用开关 | 触发器摘要徽标（手势族+关键参数，如「双指 · 按住A·轻点B」）| 规则名 | 动作摘要（图标+名，如「内置 · 音量 +」）| 生效范围（全局/仅 N 个 App/排除 N 个）| 不可用徽标（沿用现有 availability 逻辑）| 编辑箭头。
- 点击行 → 打开编辑弹窗；行上不再内联展开。
- 表头上方/下方保留既有功能：「添加规则」（打开弹窗、预填默认新规则草稿）、上移/下移、复制、删除（删除移入弹窗与行上下文菜单，二选一保留也可，但必须仍可达）、导入/导出 JSON、重置预设。

### R2. 弹窗编辑器（画板 C 三段式）
- sheet 形态（`.sheet`），宽 ~560pt，内容可滚动；结构：标题「编辑规则/新建规则」+ 名称输入 → 【触发器】手势族选择 + 手指数 + 按族参数与阈值 → 【动作】动作选择与参数 + 可用性提示（复用现有 availabilityNotice）→ 【生效范围】应用范围 + 设备范围 + 指针窗口激活 + 备注/反馈选项 → 底部「取消 / 保存」，编辑已有规则时另有「删除规则」。
- **草稿语义**：弹窗内编辑作用于草稿副本，「保存」才经 `AppModel.updateTrackpadGestureSettings` 一次性提交；「取消」丢弃。（替换现状的实时绑定即改即存。）
- 表单字段逻辑**复用现有实现**（familyFields / actionFields / 阈值控件 / kindBinding 经注册表取手指范围等），重新包装进 sheet 并绑定草稿，不重写字段语义。

### R3. 行为保持
- 规则数据模型、序列化、识别引擎零改动；保存产物与现状逐字段等价。
- 现有全局区块不动：运行状态、实时触控预览、反馈与边缘控制、规则集导入导出。
- 顺手修既有缺口：`Text("Edge")`/`Picker("Edge")` 的缺失本地化键（中文界面现显示英文）。

## Acceptance Criteria

- [ ] `swift build`、`swift test`（TrackpadGestureTests 零断言改动）、LocalizationCoverageTests、verify-localizations 全绿。
- [ ] 内联展开编辑器代码删净（无死代码残留）；行点击唯一入口是 sheet。
- [ ] 取消不产生任何设置写入；保存恰好一次 update 调用（若草稿提交逻辑可抽纯函数则配单测）。
- [ ] 新建流程：添加 → 弹窗预填默认草稿 → 保存后出现在表格末尾且立即参与识别（走现有 apply 链路）。
- [ ] 新增文案 en/zh-Hans 双语；「Edge」键补齐。

## 范围外

- 表格列排序/筛选。
